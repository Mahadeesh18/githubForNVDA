GitHub for NVDA: User Guide

GitHub for NVDA lets you use GitHub with NVDA through ordinary, fully labelled Windows windows. Browse repositories and files, work with issues and pull requests, watch GitHub Actions, read notifications, manage gists and releases, and more, without needing the GitHub website.

This add-on sets no keyboard shortcut of its own. Give the commands you want a key yourself in NVDA menu, Preferences, Input gestures, GitHub for NVDA. See Commands and their shortcuts.

  • Requires NVDA 2024.1 or later (tested up to 2026.2, including 64-bit NVDA)

Getting started

  1. In NVDA menu, Preferences, Input gestures, GitHub for NVDA, give Opens the GitHub for NVDA main menu a key of your choice, then press that key to open the main menu.
  2. Open github.com/settings/tokens in your browser and sign in.
  3. On GitHub choose Generate new token (classic) and tick repo, notifications, gist and workflow. Also tick:
    • delete_repo only if you want to delete repositories.
    • user:email only if you want to change email visibility.
    • user only if you want to edit your profile status, company, website or social media links, or use GitHub Settings (profile, blocked users, organization membership).
    • write:public_key, write:gpg_key, admin:ssh_signing_key and codespace:secrets only if you want to manage SSH keys, GPG keys, SSH signing keys and Codespaces secrets in GitHub Settings.
    • read:org if you want your private organization memberships to appear.
  4. Copy the token. Open NVDA menu, Preferences, Settings, GitHub for NVDA and paste it into Paste your personal access token. Press Test personal access token to check it with GitHub, then press OK to save it.

The token field is protected, so the token is never read aloud, unless you tick Show personal access token. To remove your token, empty the field and press OK. The token is checked with GitHub and stored encrypted so that only your Windows account can read it. It is only ever sent to api.github.com.

You can explore public repositories without a token, but GitHub then allows far fewer requests.

You can open this guide again at any time with the User Guide in Browser button at the bottom of the main menu, or from the add-on's entry in NVDA's add-on manager.

Moving around and keyboard shortcuts

  • Every window closes with Escape.
  • Tab moves between controls. Alt plus the underlined letter presses a button. The add-on makes sure these letters never clash inside a window.
  • Long text opens in a read-only edit box that you can read with the arrow keys.
  • Results and errors are spoken automatically.

Commands and their shortcuts

None of these commands has a key until you give it one. Users choose their own keys in NVDA menu, Preferences, Input gestures, GitHub for NVDA, so the add-on never clashes with other add-ons or with your own keys:

  • Open the GitHub for NVDA main menu
  • Announce how many unread notifications you have
  • Check for new notifications now and say what is new
  • Pause or resume the spoken announcements of new notifications
  • Open your notifications
  • Open My Work
  • Open the GitHub link or owner/repo that is on the clipboard

Settings

NVDA menu, Preferences, Settings, GitHub for NVDA:

  • Paste your personal access token: the token field. It is the first control. Next to it are Show personal access token, which shows the token instead of hiding it, and Test personal access token, which asks GitHub whether the token works, and Create new personal access token, which opens GitHub's token page in your browser with the permissions this add-on needs already ticked. Empty the field and press OK to remove the token.
  • Items shown on each page of a list (10 to 100)
  • Background notification check: off, or every 15 or 30 seconds, every minute, or every 2, 5, 10, 15, 30 or 60 minutes. NVDA beeps and speaks when something new arrives. The 15 and 30 second choices are the fastest: they ask GitHub more often than its usual advice of once a minute, but a check that finds nothing new is answered with "not modified" and does not use up your API requests. You can ask it to say what the notifications are about.
  • Background announcements filter: announce all new notifications, or only the ones that involve you directly (assigned to you, you were mentioned, review requested, your team was mentioned, you created it, approval requested, security alerts).
  • Mark a notification as read when you open it
  • Wrap long lines when viewing files
  • Download folder

The main menu

Personal access token

The token is set in NVDA Settings, GitHub for NVDA, not in this menu. Everything except Explore GitHub, Open Link or Repository, Bookmarked Repositories and GitHub Status needs a token.

GitHub Settings

The account settings of github.com, in the order of GitHub's own settings sidebar. See GitHub Settings.

My Work

Shows what needs you across all of GitHub: items assigned to you, pull requests waiting for your review, your open pull requests and issues, items that mention you, and what you recently finished.

My Repositories

The Sort by box and the Search box are the first two stops, then the list. You can sort by name, recently updated, private, public, forks or archived, open, create (with an optional licence) and delete. Press Enter on a repository to open it and Delete to delete it (you are asked to type the repository name first). The Applications key opens a menu with:

  • Open Repository, Rename, Edit Description, Edit Topics, Edit Website Address (with admin access) and Delete
  • Open in Browser, View README, Edit README and Add or Remove Bookmark
  • Star or Unstar, Fork Repository, Copy Clone URL, Copy Repository Link and Copy ZIP Link
  • Change Default Branch, Make Public or Make Private (with admin access), Archive or Unarchive Repository and Download Repository

Explore GitHub

See Explore GitHub below.

Open Link or Repository

Understands owner/repo, a user name, and links to repositories, folders, files, issues, pull requests, commits and workflow runs. If the clipboard holds a GitHub link it is filled in for you.

Notifications

Unread only, all, or only unread notifications that involve you directly (assigned, mentioned, review requested and so on). Copy Link puts the web address of the notification on the clipboard. View opens issues and pull requests directly and marks them read. Also mark as read, mark as done, mute a thread and mark everything as read.

Gists

List, view every file, create (filled from the clipboard, secret unless you tick public), edit single-file gists and delete.

Bookmarked Repositories

Bookmarks are saved on your computer and follow a repository when you rename it.

GitHub Status

Shows who you are signed in as and how many requests GitHub still allows.

My Profile

The profile text lists your username, name, email (shown as public only when it is), bio, company, location, website, repository and gist counts, followers and following. After Following come five extra lines. Press Tab from the text to reach the matching buttons, in the same order.

The other buttons are:

  • Change Username checks that a name is free and then opens GitHub's settings, because GitHub only allows renaming on its website.
  • Edit Name, Edit Bio, Edit Company, Edit Location and Edit Website change those fields.
  • Edit Email shows whether your primary email address is public. Choose Make Public or Make Private to flip it, or Cancel. It needs the user:email permission. If your email shows as not public, use this button, or on GitHub open Settings, Emails and turn off "Keep my email addresses private", then pick a public email under Settings, Public profile.
  • Edit Social Media Links shows one web address per line (GitHub allows up to four). Remove a line to delete a link, add a line to add one.
  • Starred Repositories, Followers and Following open lists.
  • Copy Details copies the profile text and Copy Link copies your profile link.

Editing the profile needs a token with the user permission. Pinned repositories, the contribution graph and the status use GitHub's GraphQL API and need a token.

GitHub Settings

Choose GitHub Settings in the main menu. Up and Down arrows move in the list, Enter opens an entry, Escape goes back. Lists have buttons for adding and deleting; each change asks you first when it cannot be undone.

  • Public Profile: name, bio, company, location, website, X (Twitter) username, which verified email is shown publicly, and Available for hire.
  • Account Overview and Plan: your plan, two-factor authentication on or off, disk space, private repository limits.
  • Email Addresses: add and delete addresses, make the primary address public or private.
  • SSH Keys, SSH Signing Keys and GPG Keys: list, add, copy and delete.
  • Organization Memberships: make your membership public or private, accept an invitation.
  • Repository Invitations: accept or decline.
  • Blocked Users: block and unblock people.
  • Temporary Interaction Limits: limit who can interact with your public repositories for 24 hours up to 6 months.
  • Followers, Following and Watched Repositories (with Unwatch).
  • Codespaces Secrets: see the names and delete them. Adding a secret needs encryption that NVDA does not have, so that opens GitHub.
  • API Limits: how many requests you have left.
  • More Settings on GitHub.com: everything GitHub only allows on its website (password, two-factor authentication, sessions, notifications, billing, appearance, developer settings and more). Enter opens the page in your browser.

If GitHub says permission denied, your token is missing a permission: use Create new personal access token in NVDA Settings, GitHub for NVDA, which ticks all of them.

Other people's profiles

Open them from a search, a follower list, an organization or Open Link or Repository. They show the same lines as your own profile (pinned repositories, organizations, achievements and badges, status and social media links) with the same View buttons, plus their X (Twitter) username and whether they are available for hire when set. An email address appears only when the person made it public, otherwise "not public". Organizations show their description and do not have the View buttons. Follow or Unfollow, Repositories, Starred Repositories (the repositories that person has starred; the profile text also shows how many), Followers, Following, Copy Link and Open in Browser are also there.

Explore GitHub

Search repositories, users and organizations, issues and pull requests, or code (code search needs a token). The window is laid out in this order, which is also the Tab order:

  1. Search for: repositories, users and organizations, issues and pull requests, or code.
  2. Sort by: always available and always enabled; its choices follow what you search for. Repositories: best match, most stars, most forks, recently updated. Users and organizations: best match, most followers, most repositories, recently joined. Issues and pull requests: recently updated, best match, most commented, most reactions, recently created. Code: best match only (GitHub cannot sort code results).
  3. The Search box. Press Enter in it to search.
  4. The Search button.
  5. The Results list. Enter opens the selected result.
  6. Previous Page, Next Page and Close.

Paste any GitHub link to jump straight to it. Searches are never saved: there is no search history, and any history file left by an older version is deleted when you open this window.

The repository browser

The window has, in Tab order: the repository information, a Search box, the file list and the buttons.

  • The Search box filters the files and folders of the folder you are in as you type. It announces the number of matches after you pause. Focus stays in the box until you press Tab, as in My Repositories.
  • Enter opens a folder or file, Delete deletes the selected file (with write access, after a confirmation and a commit message) and Backspace goes up one folder.
  • Buttons: Go Up, Switch Branch, Commit History, Issues, Pull Requests, Actions, Releases and More Options.
  • More Options (with write access) has:
    • Create New File: type the file name with its extension, such as notes.txt, index.html or script.py, to create any kind of text-based file. Use Upload Files for binary files such as images.
    • Create New Folder: adds a .gitkeep placeholder file, because Git cannot store empty folders.
    • Upload Files into the folder you are in, Create Branch and Delete Current Branch.
    • Upload Folder: choose a folder on your computer. It is uploaded with all its files and sub folders, keeping the structure, in a single commit. The .git folder and files over 50 MB are skipped, and files with the same name are replaced.
  • Press the Applications key (or Shift+F10) on a file or folder in the list for a menu of that item:
    • On a folder: Open Folder, Open in Browser, Copy Folder Location, Copy GitHub Link, Download Folder as ZIP, Folder History and, with write access, Upload Folder to GitHub (into that folder), Upload Files to This Folder, Create New File or Folder in This Folder, Rename or Move, Duplicate and Delete Folder.
    • On a file: Open File, Open in Browser, Copy File Location, Copy GitHub Link, Copy Raw URL, Copy File Content, Download File, File History, Properties and, with write access, Rename or Move, Duplicate, Delete, Upload Files and Upload Folder.
    • Rename, move, duplicate and folder delete each make one commit.
  • Star or Unstar, Make Public or Make Private, Edit Website Address and the copy links are on the Applications key menu in My Repositories.

Viewing and editing files

  • Control+F finds text (not case sensitive), F3 finds the next match, Control+G goes to a line, Control+S commits.
  • Writers can edit UTF-8 text files. Other encodings open read only so they are never damaged.
  • Closing with unsaved changes asks first, however you close the window.
  • File History shows the commits that changed the file.

Issues and pull requests

Open one to read the description, comments, reviews, code comments and changed files as text. You can add comments, close or reopen (issues ask whether it was completed or not planned), submit a review (comment, approve or request changes) and merge by merge commit, squash or rebase. More Actions edits the title and description, labels and assignees, and locks or unlocks the conversation. New Pull Request is in the pull request list.

GitHub Actions

Lists workflow runs for all branches or the current branch, filtered by status. Open a run to hear every job and step with its result, read the log, re-run all or only failed jobs, or cancel it.

Releases

Read notes, download files with spoken progress, and with write access create or delete releases.

Privacy and safety

  • Your token is stored encrypted for your Windows account and only sent to api.github.com.
  • Searches in Explore GitHub are not saved anywhere.
  • Dangerous actions, such as deleting a repository, need a typed confirmation. Overwriting a file always asks first.
  • Bookmarks and settings stay on your computer.

Troubleshooting

  • Permission denied: the token lacks a permission. Create a new token with the permissions listed in Getting started.
  • Organization requires single sign-on: on GitHub's token page choose Configure SSO next to the token and authorize it.
  • NVDA says it cannot read your notifications: the token has no notifications permission, or GitHub rejected it. Create a new token as described in Getting started.
  • Rate limit reached: wait, or set a token. GitHub Status shows when the limit resets.
  • A profile line says unavailable: the token may lack a permission, or GitHub did not answer. Open the profile again. Achievements depend on GitHub's public page.
  • Updating from an old release: the add-on is now named githubForNVDA. Remove the old "github For NVDA" add-on once. Your token and bookmarks are kept.
